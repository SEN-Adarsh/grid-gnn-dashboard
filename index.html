    How it works

    Scoring pipeline

    Architecture

    Label-free training

    Features come from each meter's own history and its neighbourhood — never from hidden theft labels.

    Predeclared precision target

    The flag threshold is fixed before evaluation against a 0.70 precision target. If the target is unattainable, flagging switches off.

    Built-in explanation

    Where the model supports it, every score carries an additive attribution of the feature groups behind it.

    Glossary

    NTL — non-technical loss

    Energy that is delivered but never billed: theft, meter faults, or unmetered connections. Technical loss (heat in wires) is separate and estimated.

    AT&C losses

    Aggregate Technical & Commercial loss — the utility-level loss figure combining technical losses and unbilled/uncollected energy.

    DT — distribution transformer

    The transformer feeding a local low-voltage network. Its incoming energy is metered, so missing energy can be localised to a DT.

    AMI — advanced metering infrastructure

    Smart-metering system that reports consumption at short intervals. Dropout of AMI telemetry is one of the demo scenarios.

    PR-AUC (not accuracy)

    Area under the precision–recall curve. We use it because flagged events are rare; accuracy would be misleadingly high for any model that flags nobody.

    p(theft)

    The model's decision-support score for a meter. It is not a probability of guilt and is not field-validated.

    Attribution scores (Shapley)

    An additive decomposition of a model's output across feature groups. It explains the model's arithmetic; it is not a causal claim.

    Precision target

    The share of flags that would be justified if inspected, fixed in advance (here 0.70) so thresholds cannot be tuned after seeing results.

    FPR — false positive rate

    How often honest meters get flagged. On honest meter faults our pooled FPR was 47.3% — a measured risk, stated openly.

    What did not work

    The graph model (M4) did not beat the graph-free baseline, and voltage sensing showed no established benefit. We report both rather than hiding them.

    Risks we measured

    47.3% of honest meter faults would be flagged; low-consumption customers are flagged 2.2× more often — an equity risk; 15.0% of hooking theft is invisible above the DT.

    What we need next

    Real AMI telemetry, real feeder–DT–meter topology, and a utility data partnership.

    Ready for field-data validation. Not ready for pilot deployment.

    Provenance and governance

    Data source

    All telemetry is synthetic (synthetic_india_v2 demo cohort — 500 meters, 10 DTs, 14 days, replayed from packaged assets on a reference topology). There is no Indian field dataset in this system. Scenario counterfactuals are applied to a copy; stored telemetry is never modified.

    Human-in-the-loop & enforcement

    • A flag is a request to review evidence. A field inspector verifies every flag.
    • No enforcement is automated — no disconnection, penalty, or customer notification exists in this system.
    • Flagging fail-safes off when the predeclared precision target is unattainable.
    • The audit log is written to container storage and is ephemeral — it resets on restart. It is not production-grade record keeping.
    • Traceability: every response carries the model SHA-256, config hash, and provenance notes.
