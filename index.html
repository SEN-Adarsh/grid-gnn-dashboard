Scope & provenance

  • Synthetic data only. All telemetry is synthetic (profile_source: synthetic_fallback), replayed from packaged demo assets on a CIGRE-derived reference topology. There is no Indian field dataset in this system.
  • Counterfactual scenarios. Theft / vacancy / hooking / dropout scenarios are demonstrations applied to stored telemetry; the stored source telemetry itself is never modified.

Model status & evidence

  • Not field-validated. Probabilities are decision-support scores, not field-validated probabilities of theft.
  • Benchmark (held-out DT-disjoint test, 20 seeds): M2 (own-history RF) PR-AUC 0.644 [0.584, 0.707].
  • Graph model: M4 did not beat graph-free baselines (paired M4−M3 −0.041 [−0.106, 0.049]). Voltage sensing: no established benefit.
  • Known limitations: honest-fault pooled FPR 47.3%; low-consumption customers flagged 2.2× more often; 15.0% of hooking theft is invisible above the DT.

Full evidence chain in the project deck and handoff log.

Human-in-the-loop & enforcement

  • A flag is a request to review evidence. A field inspector must verify every flag on site.
  • No automated enforcement. No disconnection, penalty, or any other action is automated by this system.
  • Ephemeral audit log. The /score audit log is written to container storage and resets on restart.
  • Traceability. Every response carries the model SHA-256, config hash, and provenance notes.
